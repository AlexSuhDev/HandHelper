# HandHelper

Локальный работающий прототип программной информационной системы: сбор числовых показателей клавиатуры и мыши во время работы с определённым сайтом, кластеризация профиля взаимодействия и адаптация интерфейса с отдельного согласия пользователя. В комплекте — демонстрационный сайт «Город рядом» с формой обращений.

Версия 2 включает временные окна наблюдения, продолжение сохранённого сеанса, проверку текста по известному образцу, задания с известной целью мыши, обучение/оценку на размеченном исследовании и экспорт самостоятельного адаптированного HTML. Реальной выборки с независимо установленными нарушениями в проекте пока нет. **Это работающая исследовательская программная система, но наличие и степень моторных нарушений у людей ею не подтверждены.**

## Что нужно человеку, скачавшему проект

- Компьютер с настольным Chrome, Edge или Firefox и включённым JavaScript.
- Физическая клавиатура и мышь для проверки настоящего сбора событий. Для просмотра синтетических сценариев они не обязательны.
- Вся папка проекта, распакованная из ZIP или полученная через Git. Нельзя переносить только `index.html`: рядом должны остаться `styles.css` и вся папка `js` с шестью скриптами. Для автоматических проверок нужна также папка `tests`.

Для запуска самой ПИС **не нужны Python, Node.js, npm, установка библиотек, аккаунт, ключи API или подключение к интернету**. Демонстрационный сайт и обучающие синтетические данные уже входят в проект. Привязки к компьютеру разработчика нет: папку можно разместить в любом доступном каталоге. Папки `.qa`, `.test-browser` и файл `browser-process.txt` — служебные артефакты разработки; для запуска и проверок они не нужны.

## Быстрый запуск после скачивания

1. Полностью распакуйте архив в отдельную папку. Не запускайте страницу из окна просмотра ZIP.
2. Откройте находящийся в этой папке `index.html` через «Открыть с помощью» → Chrome, Edge или Firefox.
3. Дождитесь появления страницы HandHelper: демонстрационного сайта «Город рядом» и панели «Наблюдение».
4. Проверьте начальное состояние: таймер `00:00 / 60:00`, оба счётчика равны нулю, кнопка «Начать час наблюдения» недоступна до согласия, интерфейс сайта стандартный.

Если страница открылась в редакторе как текст, выберите именно браузер. При проблемах с открытием через `file://` используйте локальный сервер, описанный ниже.

## Проверка работоспособности за 5–10 минут

Для быстрой проверки не нужно ждать час: синтетические сценарии отдельно проверяют анализ и адаптацию, а короткое реальное наблюдение — сбор событий. В конце можно запустить автоматические проверки.

### 1. Проверить работу демонстрационного сайта

1. В рабочей области «Город рядом» выберите тему, заполните тему обращения и описание.
2. Нажмите «Создать обращение».
3. Убедитесь, что запись появилась первой в списке «Мои обращения», а количество увеличилось с 2 до 3. Обращение никуда не отправляется.
4. В течение 20 секунд нажмите появившуюся кнопку «Отменить».

**Ожидаемый результат:** запись удаляется, количество снова равно 2, введённый текст восстанавливается в форме.

### 2. Проверить кластеризацию без ожидания часа

Перейдите к блоку «Модель и проверка сценариев» и по очереди нажмите кнопки:

| Кнопка сценария | Ожидаемый результат в блоке анализа | Предложение адаптации |
| --- | --- | --- |
| «Обычный профиль» | «Обычный профиль взаимодействия» | Отсутствует, сайт остаётся стандартным |
| «Небольшие трудности» | «Небольшая потребность в поддержке» | Уровень 1 |
| «Заметные трудности» | «Заметная потребность в поддержке» | Уровень 2 |
| «Выраженные трудности» | «Высокая потребность в поддержке» | Уровень 3 |

**Ожидаемый результат:** появляются числовые показатели и пометка «Синтетический сценарий», результат соответствует таблице. Сам выбор сценария не меняет сайт и не запускает реальный сбор. Таймер наблюдения не должен перескакивать на час: этот час указан только в готовом синтетическом отчёте.

### 3. Проверить согласие, адаптацию и отмену

1. Выберите «Выраженные трудности».
2. Убедитесь, что кнопка «Применить адаптацию» недоступна без отдельного согласия.
3. Отметьте согласие на адаптацию и нажмите «Применить адаптацию».
4. Вернитесь к рабочей области «Город рядом».
5. Нажмите «Вернуть стандартный интерфейс» в блоке результата анализа. Затем повторите применение и снимите галочку согласия на адаптацию.

**Ожидаемый результат:** после применения появляется метка «Адаптация · уровень 3»; поля и кнопки увеличиваются, темы располагаются в одну колонку. Панель HandHelper не адаптируется. И кнопка отмены, и снятие согласия возвращают стандартный вид сайта. Для сценария «Обычный профиль» адаптация вообще не предлагается.

Пока адаптация применена, нажмите «Скачать адаптированный HTML». Откройте `city-adapted.html` отдельно: это самостоятельный вариант сайта со встроенным CSS, увеличенными элементами и работающей локальной формой. Установка исходной папки для этого HTML не нужна. Экспорт очищает поля ввода, созданные пользователем обращения и задания измерения; аналитические скрипты в экспорт не включаются. Файл не содержит результатов диагностики. Исходные файлы проекта не перезаписываются.

### 4. Проверить настоящий сбор клавиатуры и мыши

1. Нажмите «Остановить и удалить данные», чтобы начать с чистого состояния.
2. В панели «Наблюдение» отметьте согласие на локальный сбор и нажмите «Начать час наблюдения».
3. Работайте именно внутри сайта «Город рядом»: вручную наберите несколько предложений в теме и описании, удалите несколько символов клавишей Backspace, перемещайте мышь между полями и темами и нажимайте на них.
4. Через несколько секунд посмотрите на панель наблюдения и показатели анализа.
5. Нажмите «Пауза», продолжите печатать и нажимать в рабочей области, затем нажмите «Продолжить» и выполните новые действия.
6. Переключитесь на другую вкладку или окно на 10–15 секунд, затем вернитесь. Для возобновления отсчёта выполните действие внутри демонстрационного сайта.
7. Нажмите «Завершить», не дожидаясь часа.

**Ожидаемый результат:**

- Во время наблюдения растут таймер, счётчик нажатий и счётчик кликов; числовые показатели появляются по мере накопления подходящих событий.
- Действия в панели HandHelper и на других сайтах не прибавляются к счётчикам. Вставка готового текста мышью не заменяет ручной набор для проверки клавиатуры.
- На явной паузе счётчики и таймер не увеличиваются. После продолжения новые действия снова учитываются.
- Время другой вкладки или окна не входит в активное наблюдение. Отображение таймера обновляется примерно раз в секунду.
- После досрочного завершения показано «Недостаточно данных» с причинами. Адаптация не предлагается. **Для короткой проверки это правильное поведение, а не ошибка ПИС.**

Во время отдельного нового наблюдения откройте в рабочей области «Уточнение данных: точность ввода и выбора объекта». Наберите показанный образец вручную и нажмите «Проверить текст». Сделайте минимум три проверки: образцы меняются. Для проверки обработки ошибок можно в одном ответе намеренно заменить символ. Система покажет число вставок/удалений/замен, необходимых для совпадения; сам ответ очистится и не попадёт в отчёт. Вставка из буфера, подсказки и IME в этом задании не засчитываются.

Затем мышью нажимайте объект, названный над сеткой. После правильного выбора цель меняется. Сделайте минимум десять попыток; один неверный выбор позволяет проверить рост счётчика ошибок. Клики по другой кнопке и фону внутри этого задания считаются неверным выбором. Клавиатурные активации и touch не смешиваются с мышью. Эти задания нужны для двух новых признаков; без них полный анализ v2 воздержится от вывода даже после часа.

### 5. Проверить экспорт и удаление показателей

1. После завершения короткого наблюдения нажмите «Скачать отчёт JSON».
2. Откройте скачанный файл в текстовом редакторе. Проверьте `source: "observation"`, фактическое `activeSeconds`, счётчики в `counts`, показатели в `features` и результат `status: "insufficient"`.
3. Убедитесь, что набранных предложений и журнала отдельных нажатий в отчёте нет. Для синтетического сценария источник будет `"synthetic"`, а не `"observation"`.
4. Нажмите «Остановить и удалить данные».

**Ожидаемый результат:** таймер и счётчики обнулены, показатели снова обозначены прочерками, результат сброшен, согласия сняты, экспорт недоступен, сайт стандартный. Скачанный на диск JSON не удаляется. Учебные обращения относятся к демонстрационному сайту и этой кнопкой не удаляются.

### 6. Проверить импорт обучающей выборки

1. Убедитесь, что наблюдение остановлено.
2. В разделе модели нажмите «Скачать пример обучающей выборки».
3. Через «Выбрать JSON с показателями» загрузите этот же скачанный файл.

**Ожидаемый результат:** появится сообщение об обучении модели на 400 сессиях с пометкой о синтетических данных. Это позволяет проверить импорт без поиска стороннего датасета. Формат своей выборки описан ниже. Отчёт одного наблюдения не является обучающей выборкой и для этого импорта не подходит.

Для проверки исследовательского режима скачайте «Пример размеченного исследования» и загрузите его через «Выбрать JSON». Ожидается обучение на 320 сессиях 64 участников и проверка на 80 сессиях других 16 участников. В статусе будут сбалансированная точность и покрытие; кнопка «Скачать результаты проверки модели» станет доступной. Это **синтетическая** проверка программы; высокие метрики этого примера не говорят о точности на людях.

Нажмите «Скачать текущую модель», затем импортируйте полученный `handhelper-model-v2.json` через тот же выбор файла. Параметры восстановятся без повторного обучения. Отдельный отчёт проверки при импорте модели не восстанавливается и не придумывается; сохраните его отдельной кнопкой.

### 7. Проверить временное окно наблюдения

1. Завершите текущее наблюдение или удалите его показатели, дайте согласие на сбор.
2. В панели наблюдения раскройте «Расписание и сохранение».
3. Укажите начало через несколько минут и конец позже начала (в пределах 24 часов). Для полноценного часа активности отведите окно с запасом, например два часа. Время интерпретируется в часовом поясе браузера.
4. Нажмите «Запланировать наблюдение» и оставьте страницу открытой.

**Ожидаемый результат:** до начала сбор не идёт; в заданный момент запускается сеанс. Он заканчивается при накоплении часа активности или при окончании окна. При коротком окне ожидается «Недостаточно данных». «Отменить расписание» отменяет ожидание, а во время запущенного по расписанию сбора также завершает этот сеанс. Просроченное окно не запускается задним числом. При закрытом браузере код не выполняется; это расписание страницы, не системная служба.

### 8. Проверить сохранение и продолжение после перезагрузки

1. Дайте согласие на сбор и отдельно отметьте сохранение числового сеанса и модели в этом браузере.
2. Начните наблюдение и выполните несколько действий. Сохранение производится раз в пять секунд, при паузе, проверке заданий и завершении, а также при уходе со страницы.
3. Перезагрузите страницу. Убедитесь, что сбор сам не начался.
4. Снова отметьте согласия на сбор и сохранение, нажмите «Восстановить сохранённый сеанс».

**Ожидаемый результат:** восстанавливаются числовые счётчики, накопленное активное время и модель; сеанс, который шёл до перезагрузки, продолжается после явного восстановления. Время отсутствия не прибавляется, текст и координаты не восстанавливаются, адаптация автоматически не применяется. При истёкшем временном окне или уже завершённом сеансе восстанавливается отчёт, а не сбор. Будущее сохранённое расписание восстанавливается только по этой кнопке. Снятие согласия на сохранение удаляет сохранённую копию; отзыв согласия на сбор или кнопка удаления удаляют и копию, и текущие показатели.

Сохраняйте и восстанавливайте на одном адресе в одном браузере: хранилища `file://`, `http://127.0.0.1:8741/` и другого порта не общие. Для устойчивого поведения рекомендуется локальный HTTP-сервер. В приватном режиме или при запрете хранения браузером сохранение может быть недоступно; приложение покажет сообщение, обычное наблюдение в памяти продолжит работать. Одновременное продолжение одной копии сеанса в нескольких вкладках не поддерживается.

## Полная проверка наблюдения в течение часа

Быстрые сценарии выше не заменяют проверку длительного реального сбора. Для неё начните **новый** сеанс с согласием и работайте внутри демонстрационного сайта до `60:00`. Уже завершённый короткий сеанс продолжить нельзя. Без отдельного согласия на сохранение перезагрузка или закрытие вкладки удаляют показатели. Продолжение сохранённого работающего сеанса описано выше.

За сеанс должны накопиться:

| Условие | Минимум |
| --- | --- |
| Активная работа | 3600 секунд |
| Нажатия клавиш | 200 |
| Измерения удержания клавиш | 100 |
| Интервалы между началами нажатий | 100 |
| Клики физической мышью | 30 |
| Пригодные маршруты мыши до клика | 20 |
| Проверки ручного набора по известному образцу | 3 |
| Попытки выбора заданного объекта мышью | 10 |

Для маршрутов перемещайте мышь между разнесёнными элементами и завершайте движение кликом. Нажатия в одной точке без перемещения не дают пригодных маршрутов. Все счётчики, включая `holds`, `flights` и `routes`, можно посмотреть в экспортированном отчёте после завершения.

**Ожидаемый результат:** при достижении часа наблюдение останавливается автоматически. Если всех событий достаточно, модель выбирает профиль либо сообщает «Профиль вне обучающей выборки». Если событий недостаточно, появляется «Недостаточно данных» с причинами. Неизвестный модели профиль и нехватка данных не приводят к адаптации. Результат реального человека нельзя заранее обещать равным конкретному кластеру; для воспроизводимой проверки четырёх вариантов используйте синтетические сценарии.

Сейчас модель обучена на синтетических данных. Эта проверка подтверждает работу программного сценария, но не подтверждает медицинскую точность определения нарушений.

## Автоматическая проверка на компьютере скачавшего проект

Тесты входят в папку `tests`. Для них запускайте страницу через HTTP: браузер может блокировать доступ тестового iframe к странице, открытой через `file://`.

### Windows — встроенный PowerShell

1. Откройте распакованную папку проекта в Проводнике.
2. В адресной строке Проводника введите `powershell` и нажмите Enter. Окно откроется в этой папке.
3. Выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Preview.ps1
```

4. Не закрывайте это окно. Должна появиться строка `HandHelper: http://127.0.0.1:8741/ (Ctrl+C to stop)`.
5. Откройте в браузере [ПИС](http://127.0.0.1:8741/), а затем [страницу автоматических проверок](http://127.0.0.1:8741/tests/index.html).

Права администратора и установка зависимостей для этого сервера не требуются. Команда задаёт политику выполнения только для запущенного процесса PowerShell; системные настройки менять не нужно.

### macOS / Linux — если установлен Python 3

Сама ПИС работает и без Python через `index.html`. Для запуска тестов по HTTP можно использовать стандартный сервер Python. Откройте терминал в папке проекта и выполните:

```sh
python3 -m http.server 8741 --bind 127.0.0.1
```

После этого откройте те же адреса ПИС и тестов, что указаны выше. Сторонние Python-пакеты не нужны.

### Как прочитать результат

Дождитесь замены надписи `RUNNING` списком результатов; обычно это занимает несколько секунд. В текущей версии успешный итог:

```text
57 passed, 0 failed
```

Каждая проверка должна иметь отметку `PASS`. Если есть `FAIL`, сохраните название проверки и текст ошибки. Проверяются математика, учёт активного времени, недостаточность данных, неизвестные профили, исключение чувствительных полей и синтетических событий, согласия, адаптация и отмена, форма обращений, ширина интерфейса от 320 до 1440 px, расстояние редактирования, сохранение и восстановление, расписание, разделение участников исследования и экспорт автономного HTML. Тестовая страница использует отдельный ключ хранилища и не удаляет реальные сохранения приложения.

В тестах час моделируется временными отметками: ждать настоящий час не нужно. Это не замена ручной проверке физических устройств и не проверка диагностической точности. Автоматический прогон при разработке выполнен в Chrome; Edge и Firefox здесь не отмечаются как отдельно проверенные этим прогоном.

Сервер принимает подключения только с текущего компьютера. Он доступен, пока открыто запустившее его окно; для остановки нажмите Ctrl+C. Это сервер разработки статических файлов, не производственный сервер.

## Сбор и время наблюдения

Сбор ограничен HTML-областью `#demo-site`, а не всей страницей, другими вкладками или операционной системой. Панель HandHelper в сбор не входит. Нужна физическая клавиатура и мышь: touch/pen, синтетические DOM-события и клики с клавиатуры исключаются из мышиной статистики. Набор через IME не включается в показатели обычного набора. Пароли, поля `data-hh-private`, одноразовые коды и поля банковских карт исключены.

Час — это 3600 секунд активности в видимой вкладке и активном окне. После последнего действия учитывается не более 30 секунд до перехода в простой. Переключение окна/вкладки и явная пауза приостанавливают отсчёт, возобновление требует нового действия. Чтение без действий дольше 30 секунд не учитывается. Календарное время сеанса может превышать час. После достижения часа сбор автоматически останавливается.

Условия достаточности данных v2: полный час, ≥200 нажатий, ≥100 измерений удержания, ≥100 интервалов набора, ≥30 кликов мышью, ≥20 пригодных маршрутов к клику, ≥3 проверки текста и ≥10 попыток выбора заданной цели. При досрочном завершении или нехватке любого показателя — «Недостаточно данных», без предложения адаптации. Продлить уже завершённый сеанс нельзя; нужно начать новый.

В памяти хранятся счётчики, средние и дисперсии по алгоритму Уэлфорда. Для сопоставления `keydown`/`keyup` временно хранятся коды удерживаемых клавиш; для маршрута — первая и последняя координаты и накопленная длина. Они очищаются при потере фокуса, паузе и остановке, не экспортируются и не включаются в сохранение. Сборщик не читает значения свободных полей, буфер обмена и полные траектории, не создаёт журнал событий. Из событий клавиатуры проверяется только тип клавиши и признак повтора. Отдельное задание сравнивает введённый образец с известной строкой в оперативной памяти по расстоянию Левенштейна, после чего поле очищается; в аналитику идут только количество проверок, правок и длина образцов.

По умолчанию показатели и модель находятся в оперативной памяти вкладки. При отдельном согласии используется `localStorage` текущего браузера: сохраняются числовой checkpoint, параметры модели, факт работы сеанса и границы временного окна; сырые события и текст не сохраняются. Нет сервера хранения, cookies, внешних шрифтов, сторонней аналитики и отправки пользовательских данных. При отзыве согласия на сбор текущие и сохранённые показатели удаляются, расписание отменяется, адаптация снимается. Кнопка удаления дополнительно сбрасывает импортированную модель. Учебные обращения относятся к самому демонстрационному сайту и удаляются при перезагрузке. Экспортированные пользователем JSON и HTML остаются на его диске.

## Математическая модель

Вектор v2 из восьми признаков:

| Признак | Определение |
| --- | --- |
| `correctionRate` | Операции `deleteContentBackward` и `deleteContentForward` / (эти удаления + операции `insertText`). Это доля исправлений, не измерение правильности текста. |
| `repeatRate` | `keydown` с `repeat=true` / учитываемые `keydown`. Повтор может быть намеренным. |
| `holdCV` | Стандартное отклонение длительности удержания / среднее; удержания 0–3000 мс. |
| `flightCV` | Стандартное отклонение интервалов между началами нажатий / среднее; интервалы 0–2000 мс. Это down-to-down, не up-to-down. |
| `pathInefficiency` | Среднее отношение длины маршрута мыши к прямому расстоянию до клика. Выборка ≤20 Гц, ≥3 точки, прямое расстояние ≥20 px, разрыв между точками ≤2 с. Маршруты к кликам не равны заранее известным движениям к цели. |
| `backgroundClickRate` | Клики вне распознаваемых интерактивных элементов / клики мыши. Не доказывает ошибку или промах. |
| `textErrorRate` | Сумма расстояний Левенштейна между ответами и известными образцами / сумма длин образцов, ограничение сверху 1. Сравниваются Unicode-кодовые точки после NFC-нормализации, учитываются регистр и пунктуация. Свободные обращения по этому признаку не проверяются. |
| `targetMissRate` | Неверные выборы внутри задания с известной целью / учтённые попытки мышью в этом задании. Цель известна до клика; случайные фоновые клики на остальном сайте сюда не входят. |

CV ограничиваются сверху 5, отношение пути — диапазоном 1–20, чтобы экстремальные выбросы не доминировали. При отсутствии наблюдений числовое значение само по себе не интерпретируется: проверка достаточности отклоняет профиль, интерфейс показывает прочерк.

Алгоритм: стандартизация `z = (x − mean) / std` по обучающей выборке → K-means++ → 10 начальных запусков, до 100 итераций → выбор минимальной суммы квадратов расстояний. `k = 4` — инженерный параметр прототипа, не доказанное количество медицинских групп. Зависимости не требуются: численный алгоритм реализован в `js/core.js`.

Метки K-means не упорядочены. Здесь центры сортируются по сумме стандартизованных признаков; большие значения **эвристически** считаются большей потребностью в поддержке. Имена: обычный профиль, небольшая, заметная и высокая потребность в поддержке. Это не степень моторного нарушения. Если расстояние до ближайшего центра больше `max(1, 1.75 × P95)` обучающих расстояний его кластера, модель воздерживается от решения. Это инженерный фильтр неизвестных профилей, не оценка вероятности и не калиброванная уверенность.

При первом запуске модель действительно обучается, но **только на 400 синтетических строках**. Результат реального наблюдения с этой моделью остаётся демонстрационным. Точность выявления нарушений, чувствительность, специфичность и медицинская применимость не установлены.

### Своя обучающая выборка

Кнопка скачивания формирует пример JSON. Предпочтительный формат:

```json
{
  "source": "synthetic",
  "rows": [
    {
      "correctionRate": 0.025,
      "repeatRate": 0.008,
      "holdCV": 0.22,
      "flightCV": 0.32,
      "pathInefficiency": 1.12,
      "backgroundClickRate": 0.03,
      "textErrorRate": 0.015,
      "targetMissRate": 0.02
    }
  ]
}
```

Показанная одна строка иллюстрирует схему: для обучения требуется 80–10 000 строк и минимум четыре разных профиля, файл ≤4 МБ. Для реальных данных укажите `source: "observation"`. Допускается также массив объектов без обёртки. Источник данных декларирует автор выборки; программа не может проверить его достоверность или независимость сессий. Обучайте на сессиях разных участников, а не на множестве окон одного человека. Модель не дообучается на одном текущем пользователе. Сырые импортированные строки не сохраняются после обучения; сохраняются параметры модели в памяти. Синтетические сценарии всегда используют отдельную демомодель, даже если загружена другая.

Перед реальным применением нужны репрезентативная выборка, добровольное участие, контроль устройств и задач, независимая оценка состояния специалистами, разделение train/validation/test **по участникам**, выбор признаков и числа кластеров, валидация клинической интерпретации, проверка ложных результатов и полезности адаптаций. Эти работы не выполнены данным прототипом. Одно взаимодействие с сайтом не позволяет достоверно установить наличие или отсутствие моторного нарушения.

### Сбор и проверка размеченного исследования

В проекте нет реальной выборки людей с подтверждёнными нарушениями. Код поддерживает её последующий сбор и оценку, но не создаёт медицинские метки автоматически.

После завершённого реального наблюдения, прошедшего все проверки достаточности, в блоке «Сбор выборки для исследования» укажите обезличенный код участника и скачайте сессию. В ней `severity: null`: исследователь должен получить независимую оценку специалиста по заранее выбранной и документированной шкале. Экспорт одной сессии не является готовой обучающей выборкой. Не помещайте реальные сессии, ФИО, медицинские документы или результаты участников в открытый GitHub-репозиторий.

Для обучения объедините сессии в JSON следующего вида; `features` содержит все восемь признаков из таблицы:

```json
{
  "version": 2,
  "source": "observation",
  "referenceMethod": "Описание независимой оценки специалистом и определения уровней 0–3",
  "rows": [
    {
      "participantId": "participant_001",
      "severity": 0,
      "features": {
        "correctionRate": 0.025,
        "repeatRate": 0.008,
        "holdCV": 0.22,
        "flightCV": 0.32,
        "pathInefficiency": 1.12,
        "backgroundClickRate": 0.03,
        "textErrorRate": 0.015,
        "targetMissRate": 0.02
      }
    }
  ]
}
```

Это пример одной строки схемы, а не достаточная выборка. Метки 0–3 означают внешние оценки от отсутствия нарушения по принятой методике до наиболее выраженного уровня; методику задаёт исследователь в `referenceMethod`, а не программа. Для программного запуска нужны 100–10 000 строк, минимум пять разных участников с каждой меткой и минимум 80 строк в обучающей части после разделения. Эти минимумы — ограничения реализации, не расчёт достаточного размера клинического исследования. Код участника: латинские буквы, цифры, дефис/подчёркивание, 1–64 символа. Противоречивые метки одного участника отклоняются: отдельные временные состояния в продольном исследовании требуют другой схемы.

Алгоритм исследовательского режима:

1. Стратификация участников по внешним меткам и отложение примерно 20% участников каждой группы для проверки. Все сессии одного кода находятся только в одной части. Генератор инициализируется фиксированным seed; разделение воспроизводимо.
2. Обучение стандартизации и K-means **только** на обучающих участниках. Данные отложенных участников не используются при вычислении средних, масштабов, центров, радиусов и соответствия меток.
3. Сопоставление каждого кластера с наиболее частой независимой меткой в обучающей части. Суммарный вес каждого участника одинаков независимо от числа его сессий. При доле победившей метки менее 60% или неоднозначности кластер остаётся без интерпретации; при попадании в него модель воздерживается от решения. В этом режиме эвристическая сортировка центров не назначает степень.
4. Оценка на отложенных участниках. Отчёт содержит `trainIds`, `testIds`, `confusionMatrix` (строки — истинная метка, столбцы — предсказанная), `abstained`, покрытие, точность с отказами как ошибками, точность с равным весом участников, recall, precision, F1, macro-F1 и balanced accuracy. Дополнительно приведены бинарные sensitivity/specificity и false-positive rate для внешней метки `0` против `1–3`. Отказы не заполняют матрицу, но входят в знаменатели recall/accuracy/sensitivity/specificity; покрытие позволяет увидеть их отдельно.
5. Экспорт модели и отдельного отчёта оценки. Программа всегда ставит `clinicalValidation: false`: сама загрузка данных и вычисление метрик не подтверждают происхождение меток, методологию или медицинскую пригодность.

Для реального исследования нужен также отдельный внешний/перспективный набор и работа с участниками: повторно подбирать параметры по одному и тому же отложенному набору нельзя. Реальная точность, доверительные интервалы и эффективность адаптаций пока не установлены. Уровни интерфейса остаются уровнями поддержки, а не медицинским заключением.

Числовые выборки без `participantId`/`severity` по-прежнему обучают обычный K-means с эвристическим порядком кластеров. Пример исследования на кнопке содержит 80 синтетических участников, по пять сессий на каждого; для него ожидаются 320 обучающих и 80 проверочных сессий. Он подходит для проверки конвейера, не для оценки моторики людей.

Форма уже использует обычные клики, семантические HTML-контролы, подписи и видимый фокус. Нет функций, требующих наведения, двойного клика или перетаскивания. ## Интеграция в другой определённый сайт

Подключите `core.js`, `collector.js`, `adaptation.js` в указанном порядке, добавьте CSS адаптации и замените `#demo-site` конкретным корнем интерфейса. Минимальный пример:

```javascript
const root = document.querySelector('#your-site');
const model = HandHelper.fit(yourTrainingRows);
const adaptation = new HandHelper.Adaptation(root);
const collector = new HandHelper.Collector(root, report => {
  const result = HandHelper.predict(model, report);
  // Покажите предложение и отдельное согласие, если result.status === 'ok'
  // и result.level > 0. Сам анализ ничего не меняет.
});

// Только в обработчике явного согласия на сбор:
collector.start();

// Только в обработчике подтверждения адаптации:
// adaptation.apply(result.level, true);
// Для отмены: adaptation.revert();
// Для отзыва согласия: collector.stop(); collector.reset(); adaptation.revert();
```

Для чужого домена скрипт не получает доступ к странице автоматически. Нужен доступ к исходникам сайта, разрешённый скрипт владельца или отдельно разработанное расширение. Для конкретного другого сайта нужно настроить корень, CSS-селекторы адаптации и задания с известными правильными ответами/целями. `recordTextTask(reference, typed, event)` и `recordTarget(hit, event)` принимают реальные доверенные события внутри заданного корня. Простое подключение скрипта не позволяет знать правильный ответ произвольного свободного текста.

Числовое состояние доступно через `collector.checkpoint()`, восстановление — `collector.start(checkpoint)`. В приложении сохранение и восстановление связаны с отдельными согласиями; при интеграции эти проверки и управление жизненным циклом нужны и на новом сайте. На многостраничном сайте одного origin это позволяет продолжать сеанс после навигации с согласованной интеграцией на всех страницах. Между разными origin хранилище не разделяется. Готовое приложение рассчитано на одну вкладку: одновременно продолжать один сеанс в нескольких вкладках нельзя. Нет системного фонового сбора, аккаунтов, сервера обучения или интеграции с медицинскими системами.

## Структура проекта

Файлы: `js/core.js` — математика, часы и расстояние редактирования; `js/collector.js` — сбор, прямые измерения заданий и числовые checkpoints; `js/adaptation.js` — обратимое изменение HTML и автономный экспорт; `js/runtime.js` — временные окна и локальное сохранение; `js/research.js` — размеченное исследование, разделение участников и оценка; `js/app.js` — интерфейс и согласия; `tests/` — проверки. Прототип не использует сторонние библиотеки. Старые модели/выборки с шестью признаками несовместимы с v2: используйте новые образцы и переобучите модель.

## Основания и ограничения

- [W3C: размер цели указателя, WCAG 2.2 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) — минимальный критерий 24×24 CSS px с исключениями.
- [W3C: увеличенный размер цели, 2.5.5](https://www.w3.org/WAI/WCAG21/Understanding/target-size) — критерий 44×44 CSS px с исключениями; ориентир для увеличенных элементов.
- [W3C: отмена действия указателя, 2.5.2](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation) — возможность отмены и использование событий отпускания.
- [Документация scikit-learn: кластеризация](https://sklearn.org/stable/modules/clustering.html) — свойства K-means и инициализация k-means++. Библиотека в проект не включена.
- [Документация scikit-learn: оценка и разделение групп](https://scikit-learn.org/stable/modules/cross_validation.html) — оценка на группах и исключение пересечения связанных наблюдений между обучением и проверкой. Реализация проекта самостоятельная, без зависимости от scikit-learn.
- [Arroyo-Gallego et al., Computer keyboard interaction as an indicator of early Parkinson’s disease, Scientific Reports, 2016](https://www.nature.com/articles/srep34468) — исследование динамики клавиатуры, не подтверждение точности настоящего прототипа.
- [Giancardo et al., Psychomotor Impairment Detection via Finger Interactions with a Computer Keyboard During Natural Typing, Scientific Reports, 2015](https://www.nature.com/articles/srep09678) — динамика удержания и влияние состояния пользователя; не основание считать все трудности набора признаком заболевания.
